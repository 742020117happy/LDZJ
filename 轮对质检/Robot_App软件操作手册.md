# Robot_App 轮对质检机器人上位机软件操作手册

> 版本：V1.3（2026-10-25）　适用软件：Robot_App（64 位）
> 运行平台：研华 MIC-770 工控机（Windows）

---

## 1. 软件概述

Robot_App 是轮对质检机器人的上位机控制软件，运行于质检工位的工控机上，负责：

- **底盘控制**：地图加载、动态初始化、巡检点导航、自动回充、手动移动
- **机械臂控制**：上电使能、轨迹执行、点动、回原点
- **精扫相机采集**：通道连接、增益设置、图像采集与上传
- **状态指示**：三色灯 + 语音播报（红灯报警 / 黄灯警告运行 / 绿灯正常静止，配合 25 条中文语音）
- **巡检任务执行**：接收 WEB 工作站下发的 START_INSPECTION 指令，自动完成"机械臂开机→脱离充电桩→加载地图→动态初始化→机械臂使能→逐点精扫→自动回充"全流程
- **数据落库与上报**：图片与任务信息自动写入数据库，关键时间点自动上报上级系统

系统网络构成：工控机连接 Magic 底盘、机械臂（CGXi）、远程 IO 站、语音播报器（RS485 串口）、精扫相机、WEB 工作站。

## 2. 启动与关闭

### 2.1 启动

1. 双击 Robot_App.exe 启动软件（启动即全屏/最大化显示）。
2. 软件**单实例运行**：若已有一个实例在运行，再次启动会弹窗提示并自动退出，请勿强行多开。
3. 软件启动后自动加载配置，左侧导航栏显示 5 个功能页面（Magic 底盘 / 相机采集 / 机械臂 CGXi / 远程 IO / 巡检任务）。
4. 底部状态栏显示：系统时间、界面刷新帧率、机械臂通讯帧率、前后相机帧率（正常应接近 10Hz）。

### 2.2 关闭

- 点击窗口关闭按钮。软件会依次停止各通讯线程并安全退出，约数秒内完成。
- 不建议在巡检任务执行中途关闭软件；如需中断，请先在"巡检任务"页点击【停止】，或由 WEB 工作站下发取消指令。

## 4. 首次使用准备

### 4.1 语音播报器音频部署（必须执行一次）

软件出厂时已生成 25 条报警语音（PA001~PA025，WAV 格式），首次使用前需拷贝到语音播报器：

1. 用 MicroUSB 数据线将语音播报器连接电脑；
2. 将音频目录下 PA001~PA025 共 25 个文件夹**整体拷入播报器内置储存根目录**（文件夹名固定五位，不可改名、不可嵌套子目录）；
3. 断开 MicroUSB，重新上电播报器；
4. 在软件"远程 IO"页或语音测试区触发试播，确认播报正常。

> 若语音日志出现"状态-播放出错（PAxxx 文件夹可能不存在）"，说明对应文件夹未拷贝成功，请重新拷贝后断电重启播报器再试。

### 4.2 配置核对

运行配置位于 Robot_App.exe 同目录的 System_DB\Communicate_DB.json 文件。首次使用前核对以下关键项（修改后用记事本保存，重启软件生效）：

| 配置键 | 说明 | 出厂值 |
|--------|------|--------|
| Magic_IP / Magic_Port | 底盘 IP / HTTP 端口 | 192.168.6.102 / 8888 |
| CGXi_Ip / CGXi_Port | 机械臂 IP / Modbus 端口 | 192.168.6.6 / 502 |
| IO_IP / IO_Port | 远程 IO 站 IP / 端口 | 192.168.6.10 / 502 |
| Voice_Com / Voice_Baud / Voice_Addr | 语音播报器串口 / 波特率 / 从站地址 | COM1 / 9600 / 1 |
| Web_Server_Ip | WEB 工作站 IP | 192.168.0.107 |
| MySql_User / MySql_Password / MySql_Database | 数据库连接参数 | 见配置文件 |
| EMIS_Url | 时间点上报地址 | 见配置文件 |
| Light_Auto | 三色灯自动联动开关（true=自动） | true |

### 4.3 巡检数据文件（Work_DB）说明

Robot_App.exe 同目录下有 Work_DB 文件夹，内含两个巡检数据文件，作用与配置方法如下。两个文件均为 JSON 格式，须使用 **UTF-8 编码**保存（记事本"另存为"→编码选 UTF-8，勿用 ANSI/GBK，否则中文乱码导致巡检数据错误）。

#### 4.3.1 Axis_Position.json —— 一键巡检测试指令文件

**作用**：巡检任务页【开始】按钮的一键巡检测试数据源；内容为一条完整的 START_INSPECTION 巡检指令样例，也是 WEB 工作站下发指令的格式范例。

**内容示例**：

```
{
    "Cmd_Name": "START_INSPECTION",
    "Value": true,
    "Checksum": "A1B2C3D4",
    "wheelsetCount": 1,
    "tasks": [
        {
            "taskId": "202610241506&20260109-0029&109-GBD-04990&CR400BF",
            "carType": "CR400BF",
            "wheelsetKind": "GBD",
            "axleType": "RD3A",
            "wheelsetNo": "109 GBD 04990",
            "axleNo": "AX-RD3A-261023-01",
            "sendUnit": "上海动车段",
            "startTime": "202610231631",
            "repairLevel": "三级修",
            "wheelsetPosition": {
                "posId": 1,
                "mapPointName": "Lunduizhijian001",
                "positions": ["P1", "P1.1", "P2", "P3", "P4", "P4.1", "P5", "P6"]
            }
        }
    ]
}
```

**各字段说明**：

| 字段 | 说明 | 配置方法 |
|------|------|---------|
| Cmd_Name | 指令名，固定 START_INSPECTION | 不改 |
| Value | true=开始巡检，false=取消 | 测试时保持 true |
| Checksum | 校验串，软件仅检查非空 | 保持 A1B2C3D4 或任意非空值 |
| wheelsetCount | 工位数：1=单工位，2=双工位 | 按实际工位填写；填 2 时 tasks 数组须放两个任务对象 |
| taskId | 任务唯一号（时间&轮对信息&车辆信息） | 每次测试可随意修改，不影响执行 |
| carType | 车型 | **必须与 InspectionPlan.json 的一级键名完全一致**（如 CR400BF） |
| wheelsetKind | 轮对类型（动对/拖对） | **必须与 InspectionPlan.json 的二级键名完全一致**（如 GBD） |
| axleType / wheelsetNo / axleNo | 车轴型号/轮对号/轴号 | 业务标识，按实际轮对填写 |
| sendUnit | 送修单位 | 业务标识 |
| startTime | 开始时间（yyyyMMddHHmm） | 业务标识 |
| repairLevel | 修程（如三级修/四级修） | 业务标识 |
| posId | 工位号（1 或 2） | 按实际工位填写 |
| mapPointName | 巡检地图名 | 必须与底盘已加载的巡检地图一致（出厂为 Lunduizhijian001） |
| positions | 巡检点序列 | 使用 P1 / P1.1 / P2 / P3 / P4 / P4.1 / P5 / P6 中存在的点位；**点位名必须在 InspectionPlan.json 对应车型-轮对类型下已配置轨迹** |

#### 4.3.2 InspectionPlan.json —— 巡检配方文件

**作用**：定义"车型 + 轮对类型 → 巡检点 → 机械臂轨迹号"的对应关系。自动巡检时，软件按此配方将每个巡检点转换为机械臂需执行的轨迹程序编号。

**内容示例**：

```
{
  "CR400BF": {
    "T3C": { "P1": [22], "P1.1": [28, 29], "P2": [23], "P3": [24],
             "P4": [25], "P4.1": [30, 31], "P5": [26], "P6": [27] },
    "GBD": { "P1": [13], "P1.1": [15, 18], "P2": [16], "P3": [17],
             "P4": [19], "P4.1": [21, 20], "P5": [14], "P6": [12] }
  },
  "CRH380B": {
    "M3B": { "P1": [32], "P1.1": [34, 37], "P2": [35], "P3": [36],
             "P4": [38], "P4.1": [40, 39], "P5": [33], "P6": [41] },
    "T3B": { "P1": [1], "P1.1": [7, 8], "P2": [2], "P3": [3],
             "P4": [4], "P4.1": [10, 20], "P5": [5], "P6": [6] }
  }
}
```

**结构层级**：`车型 → 轮对类型 → 巡检点 → 轨迹号数组`

**配置方法**：

1. **新增车型**：在最外层增加车型键（键名与任务指令中 carType 字段一致），其下按轮对类型分层；
2. **新增轮对类型**：在对应车型下增加轮对类型键（键名与任务指令中 wheelsetKind 字段一致）；
3. **配置巡检点轨迹**：每个巡检点对应一个轨迹号数组；数组顺序即机械臂执行顺序；
4. **轨迹号来源**：轨迹号为机械臂控制器中已烧录的轨迹程序编号，**修改前必须与机械臂工程师确认实际烧录的轨迹号**，写错会导致机械臂执行错误动作；
5. **一个点可对应多条轨迹**（如 "P1.1": [28, 29] 表示该点依次执行 28 号、29 号两条轨迹）。

**注意事项**：

- 软件启动时自动加载本文件；修改后须重启软件生效；
- 巡检指令中使用的点位若在配方中不存在，任务会立即失败并语音报警（红灯"设备故障"）；
- 保持 JSON 语法正确（逗号、引号、花括号配平），编辑后可用记事本打开确认无乱码；两个文件若有中文内容，必须 UTF-8 编码。

- 点击【连接】建立与精扫相机的通道连接；
- 增益等参数按质检工艺设置；巡检过程中由程序按配方自动下发采集指令。

## 6. 自动巡检作业流程

1. **WEB 下发指令**：工作站下发 START_INSPECTION（含轮对信息、地图名、点位序列 P1~P6 等），软件校验字段齐全后开始执行；
2. **工序顺序**：机械臂开机 → 脱离充电桩 → 刷新地图列表 → 加载巡检地图 → 刷新导航点 → 动态初始化（P001）→ 机械臂使能 → 逐巡检点导航+精扫（播报"巡检运行中，请注意避让"）→ 精扫结束 → 自动回充 P0 → 完成（状态灯转绿）；
3. **过程播报**：初始化完成、定位完成、回原点等关键节点均有语音播报；
4. **异常处理**：任一工序失败立即停止，状态灯转红并播报对应报警语音；日志与报警列表记录详情，WEB 工作站可查询；
5. **数据落库**：巡检开始/结束、图片采集等数据自动写入数据库，关键时间点自动上报。

## 8. 常见故障排查

> **日志定位方法**：所有模块日志统一写入 exe 同目录 Debug_DB\软件操作日志_yyyyMMdd.log，格式为 [时间][等级][模块][事件] key=value。排查故障时优先按等级过滤：
> - 故障/报警：搜索 [ERROR]（如 [ERROR][ARM][CoilWrite] failed count=1/5）
> - 异常但可恢复：搜索 [WARN]（超时/重试/配置缺失）
> - 巡检过程追踪：搜索 [INFO][WORK][Flow]（start/finish/cancel 节点含任务ID与轮对号）
> - 通讯追踪：[INFO][CHASSIS][Connect]、[VOICE][Heartbeat]、[HTTP][Request]（HTTP 帧为 DEBUG 级，需 Log_Level=DEBUG）
> - 敏感字段（Token/密码/Base64）不会出现在日志中，属正常现象



> **日志定位方法**：所有模块日志统一写入 exe 同目录 `Debug_DB\软件操作日志_yyyyMMdd.log`，格式为
> `[时间][等级][模块][事件] key=value`。排查故障时优先按等级过滤：
> - 故障/报警：搜索 `[ERROR]`（如 `[ERROR][ARM][CoilWrite] failed count=1/5`）
> - 异常但可恢复：搜索 `[WARN]`（超时/重试/配置缺失）
> - 巡检过程追踪：搜索 `[INFO][WORK][Flow]`（start/finish/cancel 节点含任务ID与轮对号）
> - 通讯追踪：`[INFO][CHASSIS][Connect]`、`[VOICE][Heartbeat]`、`[HTTP][Request]`（DEBUG 级需 Log_Level=DEBUG）
> - 敏感字段（Token/密码/Base64）不会出现在日志中，属正常现象

| 现象 | 排查步骤 |
|------|---------|
| 软件无法启动/提示已运行 | 检查是否已有实例在运行，用任务管理器结束后重试 |
| 底盘/机械臂/IO 指示灯红 | 检查对应网线、设备是否上电，核对 IP 配置是否与"4.2 配置核对"表中的值一致；模块断线后会自动重连 |
| 语音日志"连续3次无应答" | 检查 COM1 接线与播报器供电；核对波特率 9600、无校验、从站地址 1 |
| 语音日志"播放出错 PAxxx 不存在" | 按"4.1 语音播报器音频部署"重新拷贝音频文件夹到播报器内置储存根目录 |
| 相机帧率远低于 10Hz | 检查底盘网络连接质量；有线网络下应稳定 10Hz |
| 巡检任务中途失败 | 查看巡检页日志与报警列表定位失败工序（开机/脱桩/地图/初始化/使能/精扫/回充） |
| 日志文件过大 | 软件自动治理：操作日志超 500MB 自动清理至 100MB，无需人工处理 |

## 9. 安全注意事项

1. 机械臂运行与小车移动期间，人员须处于安全区域，注意避让（对应语音播报）；
2. 手动移动小车时必须目视操作（软件有语音提示）；
3. 急停按钮按下后需人工复位确认，方可恢复作业；
4. 巡检过程中请勿随意关闭软件或断开设备电源；
5. 三色灯手动模式（Light_Auto=false）下系统不自动报警，仅建议调试时使用，正常作业保持 Light_Auto=true。
